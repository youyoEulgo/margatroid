# address

address提供实体对外寻址和磁盘文件定位，不提供Plugin、图书馆组件、通用资源集合、类型注册表或资源生命周期管理。

## 依赖

address位于core层，只依赖mecs、标准库及通用基础库，不依赖其他领域core或plugin。领域plugin使用address解析外部输入；其他领域core不依赖address。

## 实体寻址

Address作为独立组件挂载到需要公开寻址的Entity。World扩展只提供按地址查找Entity和地址查重；不维护第二份索引。挂载或改名的调用方在同一ECS修改流程中先查重，再写组件。

外部地址在入口解析一次，内部组件关联、事件和Handler使用完整Entity。异步操作保留解析时的Entity，不按旧地址重新寻找替代实例。对外响应需要地址时读取Address组件。

## 文件定位

资源字符串使用type:scope/name[:tag]，缺省tag为latest。文件定位函数将字符串解析为真实文件路径；磁盘布局和资源入口由各资源领域约定。实体地址查询和文件定位互不兜底。

导入后只登记alias与路径，不保留来源地址或加载内容。工具、提示词、沙箱和Driver分别提供自己的集合组件，统一使用BTreeMap<String, PathBuf>，读取和解析方法由对应领域提供。

## 随用随取

每次使用从登记路径重新读取和解析，不保存长期内存副本；文件删除、权限变化或格式错误直接返回失败，不回退旧内容。实际打开文件时仍检查路径和执行权限。

一次推理、工具执行、沙箱执行或Driver启动可持有本次所需的临时数据，文件变化不修改在途操作。Driver在每次启动时读取程序，不在运行中热替换。显式写入对话Block的内容属于对话数据，不是文件资源缓存。
