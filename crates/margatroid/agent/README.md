# Agent

本轮共享Client槽位、统一写入口与异步监控已实现，尚未提交。具体函数和边界见本领域DESIGN及[DTO说明](../dto/README.md)；运行进程需使用新构建。
agent_core定义Agent自身组件、生命周期状态、事件和错误，目标通过client_core共享发送能力连接网络，仍不依赖DTO或服务器plugin。agent_plugin依赖agent_core、address和所需领域core，负责跨领域生命周期编排，不依赖其他plugin。

本文其余业务契约沿用已提交基线，新同步路径以当前实际实现为准。Tools是当前Agent唯一工具记录集合，保存alias、path、description、input_schema及私有执行归属owner_task_id和binding；后两者仅经执行context提供，不进入模型schema或公开wire。动态定义属于注册目标Agent完整Entity及Driver实例，可以绑定同Workspace其他Agent的实际任务作用域；绑定任务关闭或目标实例结束时撤销，已受理调用独立收口；数据库和settings继续承担原有持久化业务。MCP协议由工具侧处理。

## 同步受理

状态只包含Starting、Running、Error、Stopping，turn独立。Handler在一次同步调用中检查状态白名单并切换状态，随后提交异步闭包。

Starting从实体创建覆盖资源挂载和应用初始化，资源挂载完成仍为Starting；MCL在Starting/Running可用，只有ready进入Running。Running无turn允许start_turn，有turn允许推理及工具请求；开始/中止/结束只改变turn。Error拒绝普通MCL，仅接受查询及清理，Stopping表示实际关闭监督。Starting/Running/Error可停止，重复Stopping拒绝。重启保留已有未完成工具任务的受理检查，通过检查后真实先停止旧运行再Starting，不存在Restarting。

stop_agent_system、restart_agent_system、start_agent_system依次挂载于同一Schedule，直接使用mecs按添加顺序同步执行的机制。同帧关闭优先于重启；先受理者同步修改状态，后者按白名单拒绝。不增加统一生命周期事件、排序队列或手写优先级分发器。优先级不取消前一帧已受理的操作。

## 请求

StartAgent和RestartAgent使用相同字段：id、workspace Entity、name、AgentStartParameters、oneshot reply。启动创建Entity；重启在指定Workspace内按名称定位成员，随后固定使用完整Entity。新API入口先全量重载Workspace定义并从本次发布缓存取得成员参数，再以既有请求字段提交；Agent底层使用这些新启动参数，完整结束后通过原reply返回，不另发启动或重启结果事件。

## 异步流程

启动参数的文件路径固定为Workspace定义所在目录的agents/<成员名>/state.sqlite及setting.toml；不接受旧设置文件名或兼容读取。setting.toml缺失时仅从Driver同名默认模板创建，已有文件不覆盖。持久Block由存储领域放在state.sqlite.blocks/<Block逻辑名>/，TEMP Block与其快照仅保留内存。

启动受理后创建Starting实体，并保留明确的AgentStartParameters。持久配置不存在时，受监督blocking worker从initial_settings_path读取并校验初值，通过原open_storage持久化；配置已存在时不再读取或覆盖初值。ui_path仅是实际UI目录引用，每个Agent直接监控这一路径，不复制UI，不依赖程序目录或旧Agent本地UI。Agent不创建Lua VM，挂载完成仍须显式ready。配置和UI引用随原创建参数保留，网络重启不会用Workspace成员的程序目录替换它们。

关闭受理时同步关闭新操作受理。关闭闭包只请求Agent自有任务/推理取消，递归停止直接子Agent，不终止创建者VM，等待活动真实退出及MCL收口；结果Handler确认后销毁Entity。

重启依次在Stopping下完成stop_runtime，真实资源退出后转Starting并重新startup；保留协调Entity但创建新AgentSession，资源挂载完成不代替ready。StartAgent建立StartupBarrier；StopAgent先等待在途初始化的blocking worker及全部领域回复真正完成，不能提前销毁宿主。

每个步骤和最终结果核对完整Entity及对应生命周期状态。oneshot关闭或闭包异常不是清理完成证明；无法确认清理时保留宿主，发送失败结果。启动或重启挂载成功保持Starting，关闭成功销毁Entity；启动或重启失败且清理完成时销毁Entity。

## 运行组件初始化

Agent启动闭包在原有运行组件准备阶段同一轮发送InitToolTasks和InitInference，再用tokio::join!等待两个oneshot；与原有资源初始化一起完成，全部成功后才启动Driver。任何一项失败也先收齐另一项结果，再统一处理启动失败。重启复用同一启动流程。

InitToolTasks由tool_plugin挂载空ToolTasks，InitInference由inference_plugin挂载current=None的ActiveInference。Agent只依赖这两个领域core中的事件契约，不直接创建对应组件，不新增统一execution组件或System。

## 数据归属

Agent的同步可见状态改为共享只读视图，状态、turn、故障及公共信息只经update_agent修改；业务资源事实仍由原领域持有，公共Tools/沙箱/模型值由相应成功写入口同步维护。Address独立挂载，仅供边界寻址。Driver运行组件、MCL队列、数据库、历史和各资源集合由各领域core定义，作为并列组件挂到Agent Entity。

中止控制事件被受理后，调用方plugin同步调用agent_abort_turn检查并清除turn，随后取消ActiveInference.current句柄，并由ToolTasks::abort_unreturned原子强制交付未return任务的原调用中止结果、请求终止清理；已return未finish后台任务保留；专属控制事件直接进入PRE_UPDATE完成本帧裁决；agent_core不额外提供中止结果事件或中止闭包。Agent始终Running，turn是否为空表达回合有效性，结束等待实际推理退出后清turn。turn已空或不匹配的重复中止直接拒绝，不保存上轮中止关联。Agent不修改Workspace配置文件。新API入口与Workspace生命周期共用全量重载能力，取得同一次发布缓存中的成员参数后调用Agent；底层Agent不另行扫描或按名称单独读取Workspace文件。

基线已包含AgentResources和UI观察。本轮将监控创建/取消移到实际来源和存储的安装/替换/停止流程，不再让DTO活动帧扫描发现它们。生命周期与中止的原有受理顺序保留。

StartTurn、FinishTurn和AbortTurn同属唯一Agent更新入口，turn变化和完整Agent列表变化直接投递共享槽位。错误、资源导入、动态工具移除、沙箱选择及模型公共信息提交也必须更新同一派生视图。来源替换先失效旧租约并等待UI/记录监控真实结束，不能使旧实例迟到更新复活。


当前工作树已实现统一Lua：复用既有资源挂载、Storage、MCL队列、任务监督、进程回收及同步入口。Workspace先启动独立Lua任务；Agent创建由公共Lua注入能力提交StartAgent，Agent不再启动/持有/终止Lua VM。执行者与目标分开，Agent归属Workspace或父Agent，配置按明确初值文件初始化持久化，UI按创建时传入目录直接监控，模型通过EFFECT model_set配置。公共mcl.execute指定目标，wait(agent)登记本次唤醒句柄；关闭Agent使用margatroid.agent:stop(address)注入方法提交原StopAgent并外部监督，不经过MCL。EFFECT tool_call只接收调用数组。Driver专用manifest依赖裁剪取消；工具发现元数据保持。初始化/委托/子代理应用未实现；前端源码不在本轮修改范围内。

四态契约：Agent/Workspace公开starting、running、error、stopping；Agent挂载完成不是ready，MCL允许starting/running，推理和工具仅running且有效turn。Lua创建的Agent在返回信息前绑定实际执行实例与AgentSession监控；执行异常真实收口后写Agent日志，原提交探针直投Clients，再通过AgentException发布error，正常结束和取消不误报故障，旧会话解绑。关闭使用Lua agent.stop注入，不提供MCL agent_stop。

agent_ready作为Agent领域统一入口验证状态和turn，MCL只转交；回合开始/结束/中止也由Agent core方法验证。MCL不按具体指令维护第二套受理条件。

Agent创建注入接口为owner/name/config_path/ui_path，拒绝旧resource_dir创建参数。配置仅首次从config_path初始化至Agent持久setting.toml，后续重启保留已修改配置；ui_path始终直接引用与监控，不创建Agent本地UI，不复制、覆盖、删除已有UI副本，也不把旧副本作为回退来源。Lua程序加载只读取程序文件，不推导或读取同目录配置。
